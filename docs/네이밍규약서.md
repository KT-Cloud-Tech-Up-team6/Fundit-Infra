# Fundit 인프라 네이밍규약서

이 문서는 `Fundit-Infra`가 만드는 AWS 리소스와 Terraform 변수의 이름 규칙을 다룬다. 레포 구조와 협업 규약은 [`README.md`](../README.md)를 본다.

## 1. 네이밍 대원칙

```
fundit-<environment>-<리소스종류>[-<식별자>]
```

| 대상 | 규칙 |
|---|---|
| project_name | `fundit` (소문자) |
| AWS 리소스 이름 | 소문자 kebab-case |
| Terraform 변수 | snake_case |
| S3 버킷 | 소문자, 전역 유일, 필요 시 랜덤 접미사 |

소문자를 쓰는 이유: S3 버킷과 ECR 저장소는 AWS가 대문자를 허용하지 않는다. 나머지 리소스도 Fundit-backend의 docker-compose 네이밍(전부 소문자)과 맞추기 위해 소문자로 통일한다.

### 4-5. 애플리케이션 이미지 CI

Issue #37의 이름을 사용하며, 공용 ECR과 함께 bootstrap에서 관리한다.
첫 연동 대상은 개발 이미지 CI이고, 운영 배포 권한을 뜻하지 않는다.

| 리소스 | 이름 | 이미지 Push 대상 |
|---|---|---|
| Backend CI IAM Role | `fundit-backend-ci-role` | `fundit-backend` |
| Frontend CI IAM Role | `fundit-frontend-ci-role` | `fundit-frontend` |
| 각 Role의 inline policy | `ecr-push` | 해당 Role의 ECR 한 개 |

허용 GitHub 저장소·브랜치와 연동 절차는 [ECR CI 인증 문서](./ecr-ci-oidc.md)를 따른다.

### 4-6. GitOps 개발 EC2 배포

개발 배포용 인증과 실행 문서는 기존 GitHub OIDC 공급자가 있는 bootstrap에서 관리한다.

| 리소스 | 이름 | 허용 대상 |
|---|---|---|
| GitOps 배포 IAM Role | `fundit-dev-gitops-deploy-role` | `Fundit-GitOps`의 `dev-deploy` Environment |
| Role inline policy | `ssm-dev-deploy` | 전용 SSM 문서와 개발 앱 EC2 |
| SSM Command document | `fundit-dev-deploy-gateway` | 검토된 GitOps 커밋의 Gateway 배포 |

서버 배포 사용자는 `fundit-deploy`, 관리자가 설치하는 실행 파일은
`/usr/local/libexec/fundit/deploy-dev-revision`으로 고정한다.
EC2 접근 경계와 설정 순서는 [GitOps 개발 배포 문서](./gitops-dev-deploy.md)를 따른다.

## 6. 팀 공유 계약

### 6-1. gateway-service 라우팅 (포트 8080)

| 경로 | 대상 |
|---|---|
| `/api/v1/auth/**` | auth-service |
| `/api/v1/members/**`, `/api/v1/wishes/**`, `/api/v1/addresses/**`, `/api/v1/terms/**` | member-service |
| `/api/v1/payments/**`, `/api/v1/refunds/**`, `/api/v1/settlements/**` | payment-service |
