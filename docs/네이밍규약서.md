# Fundit 인프라 네이밍규약서

이 문서는 `Fundit-Infra`가 만드는 AWS 리소스와 Terraform 변수의 이름 규칙을 다룬다. 레포 구조와 협업 규약은 [`README.md`](../README.md)를 본다.

## 1. 네이밍 대원칙

```
fundit-<environment>-<리소스종류>[-<식별자>]
```

| 대상 | 규칙 |
|---|---|
| project_name | `fundit` (소문자) |
| AWS 리소스 이름 | 소문자 kebab-case |
| Terraform 변수 | snake_case |
| S3 버킷 | 소문자, 전역 유일, 필요 시 랜덤 접미사 |

소문자를 쓰는 이유: S3 버킷과 ECR 저장소는 AWS가 대문자를 허용하지 않는다. 나머지 리소스도 Fundit-backend의 docker-compose 네이밍(전부 소문자)과 맞추기 위해 소문자로 통일한다.

## 2. 뿌리 변수

## 4. 리소스 이름 사전

### 4-1. network

| 리소스 | 이름 |
|---|---|
| VPC | `fundit-dev-vpc` (10.0.0.0/16) |
| Subnet public | `fundit-dev-public-sn-1`, `fundit-dev-public-sn-2` |
| Subnet private | `fundit-dev-private-sn-1`, `fundit-dev-private-sn-2` |
| Subnet db | `fundit-dev-db-sn-1`, `fundit-dev-db-sn-2` |
| 보안그룹 | `fundit-dev-app-ec2-sg` |
| EC2 | `fundit-dev-app-ec2` |

### 4-2. edge

| 리소스 | 값 |
|---|---|
| Route53 호스팅존 | `infrastudy.store` |

### 4-3. storage

| 리소스 | 이름 |
|---|---|
| tfstate S3 | `fundit-tfstate-team6` |
| ECR | `fundit-backend`, `fundit-frontend` |

### 4-4. data — 백엔드 서비스 DB

| 서비스 | DB_NAME | 포트 |
|---|---|---|
| auth-service | `auth_service` | 5432 |
| member-service | `member_service` | 5433 |
| project-service | `project_service` | 5434 |
| order-service | `order_service` | 5435 |
| payment-service | `payment_service` | 5436 |

컨테이너/네트워크 이름 패턴: `fundit-<service>-postgres`, `fundit-<service>-net`. 새 서비스가 추가되면 포트를 5432부터 순서대로 1씩 늘린다.

## 6. 팀 공유 계약

### 6-1. gateway-service 라우팅 (포트 8080)

| 경로 | 대상 |
|---|---|
| `/api/v1/auth/**` | auth-service |
| `/api/v1/members/**`, `/api/v1/wishes/**`, `/api/v1/addresses/**`, `/api/v1/terms/**` | member-service |
| `/api/v1/payments/**`, `/api/v1/refunds/**`, `/api/v1/settlements/**` | payment-service |

환경변수 계약: `<SERVICE>_BASE_URL`(예 `AUTH_SERVICE_BASE_URL`, `MEMBER_SERVICE_BASE_URL`), `INTERNAL_API_KEY`(다운스트림 공유 시크릿).

### 6-2. 결제

PG사: 토스. 웹훅 경로 `/api/v1/payments/webhook/toss`.

### 6-3. Redis

auth-service만 사용. 본인인증 코드 임시 저장용(`RedisIdentityVerificationStore`).
